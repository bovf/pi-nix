## Compatibility changes

### Same-compilation schema artifact

Pi 1.5 validates tool arguments using `pi-schema`. Its release Nix recipe's
install lock includes that workspace but omits its compiled source override,
causing an integrity lookup failure. The existing thin bridge now packs the
compiled schema alongside Durable/Chord and supplies it through the original
`importNpmLock` source-override interface. No core recipe/catalog/lock/hash fork
or registry substitute is introduced. Exact upstream-match/obsolescence guards
require retirement when upstream owns the mapping. A mandatory installed probe
checks same-release schema import, validation/errors/coercion and caller preservation.

The native host inventory includes schema and its formats entry, with matching
host versions. Authored extension sources have no observed `Type.Refine`,
`BigInt`, `Undefined`, codec/transform or `Format.Set` tool-schema patterns;
this is source inspection, not a claim that every tool was interactively exercised.

### REA-compatible Ghidra, not a global rollback

Latest stable npm REA remains **6.8.0**, whose doctor accepts only Ghidra 12.1.x.
New nixpkgs supplies 12.2/JDK25. With operator approval, only REA uses the
[12.1.4 source pin](../overlays/rea/ghidra.json) and JDK21. The updater verifies
its exact stable release asset/official SHA256 and the hash-checked archive.
Other consumers retain nixpkgs Ghidra12.2.

Nix patching of the old prebuilt decompiler caused a startup crash. The native
decompiler/Sleigh components are rebuilt from C++ sources in that exact approved
archive, using declared Nix tools; Java/archive content stays release-owned.
Doctor, unchanged 229-tool/6-prompt catalog, no-write negatives and the complete
synthetic ELF Ghidra/Rizin/objdump checks pass. No target ELF is executed, engine
version guard relaxed, omitted backend installed or privilege added.
